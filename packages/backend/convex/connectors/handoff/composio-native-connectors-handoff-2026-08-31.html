Architecture handoff

Current Composio path

1. Publishintegrations_public and per-action rows hold Composio-shaped Store metadata.
2. Discover/api/native-integrations/catalog feeds runtime live/cache/bundled catalog resolution.
3. Connect/statusStore enablement and connector_status resolve backend-managed Composio accounts.
4. Executeconnect.call crosses the CLI/worker broker, validates action/input/account, then calls backend /run.
5. ProviderThe backend invokes Composio /execute; Composio owns OAuth custody and provider calls.

First-party target

Provider registry

Non-secret manifests pin authorization/token/identity/revocation endpoints, exact callback paths, scope groups, refresh semantics, and verification status. One app per provider per environment.

Hosted OAuth

Authenticated connect start creates hashed state, encrypted PKCE verifier, owner/provider/scope binding, secret version, and expiry. The callback consumes state once before exchange and returns only an opaque attempt result.

Account model

oauth_connect_attempts, oauth_accounts, encrypted oauth_credentials, connector/account bindings, and per-connector rollout records separate product identity from executor identity.

Encrypted custody

AES-GCM envelope encryption with versioned master-key rings; tokens decrypt only inside backend executors. Refresh uses generation-safe expiring leases and preserves omitted refresh tokens.

Native execution

Canonical actions map to fixed provider origins, schemas, required scopes, operation class, response bounds, redaction, and explicit retry policy. Models cannot choose auth headers or arbitrary hosts.

Independent API keys

Owner-scoped encrypted key slots remain separate from OAuth. Activation requires explicit provider enablement plus a representative-call verification allowlist.

Provider-neutral broker

The backend resolves connector, action, account, scope, route, and executor. Desktop/mobile receive status, never provider tokens.

Safe rollout

composio_only → read-only shadow → deterministic canary → first_party_preferred → first_party_only. Never dual-run or silently replay a write; uncertain writes return ambiguous_write.

Production callback invariant: exact HTTPS non-loopback callbacks only. On 31 August both https://benevolent-minnow-586.convex.site/api/connectors/oauth/callback and https://connect.stella.sh/ returned HTTP 404. No provider should be registered or activated against that state.

Ordered continuation plan

  1. Freeze evidence, not development. Keep all connector worktrees and the local connectors-wip tip. Record commit/path manifests. Do not clean the primary checkout or push the local branch as if it were release-ready.
  2. Create a clean integration worktree from current origin/master. The current default is the product baseline. Never integrate in the dirty primary checkout.
  3. Port the shared core first. Schema, encrypted OAuth/API-key custody, refresh leases, callback/start/status/disconnect, provider registry, provider-neutral broker, rollout rows, redaction/audit, account deletion/migration, and package smoke tests.
  4. Restore a real HTTPS callback before provider registration. Wire connect.stella.sh or an approved equivalent, add no-store/no-referrer behavior, and prove start/callback/status end to end in non-production.
  5. Port Google Workspace next. Bring exact nine-scope parity and native action fixes onto the new integration branch, run focused tests, create a reviewer-accessible staging build, then unblock Console capture and the continuous video.
  6. After owner approval, answer Google. Fill the draft only with the validated movie, clean-device reviewer credentials, exact navigation, and scope capture. Reply in the existing thread; do not create a new submission.
  7. Port Microsoft and social families. Microsoft first, then X, YouTube, Meta, LinkedIn, Reddit, Slack. Register apps only after the callback is live; stop at 2FA, payment, business verification, legal terms, or admin consent.
  8. Port OAuth SaaS families in bounded groups. Productivity/CRM/developer/design executors, each with exact stable IDs, fixed origins, app registration, real connect/read/write/refresh proof, and an independent rollout row.
  9. Port API-key and hosted families last. Reapply the encrypted API-key core and reviewed provider contracts. Keep 1Password dormant until network-enforced egress exists; keep Snowflake and 21RISK externally gated.
  10. Canary connector by connector. Composio-only, read-only shadow where safe, deterministic first-party canary, preferred, then first-party-only after rollback proof. Never dual-execute or auto-fallback an ambiguous mutation.
